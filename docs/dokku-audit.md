## Summary

dokku-compose declares the settings of an app on one Dokku host: create, domains, ports, proxy,
nginx, certs, storage, networks, env, scale, process settings, checks, logs, registry,
scheduler, builder (Dockerfile only), docker options, git deploy branch, plugins, and postgres
and redis services with links and postgres backups.

The gaps fall into two groups:

1. **Gaps in features it already has.** A cert file and `checks:` are re-applied on every
   `up`, and `diff` cannot see a replaced cert file; a changed
   datastore version or image is ignored without a word; postgres backup state lives in a
   global env var; global `env:` and `docker_auth:` never remove anything; several property
   lists trail Dokku 0.38.31. These come first in [Priorities](#priorities).
2. **Namespaces it does not touch.** `resource`, `cron`, `git:auth`, `apps:lock`, `builds`,
   `scheduler-docker-local`, `ssh-keys`, non-Dockerfile builders and buildpacks, the other
   proxies, other datastore plugins and `scheduler-k3s`.

## Priorities

Fix the features dokku-compose already has before adding new namespaces: a user who declares
one of those keys today gets a wrong or noisy result. Sizes are story points.

### Fix existing features

| # | Item | Why | Size |
|---|---|---|:-:|
| F1 | ✅ **Settings re-applied on every `up`; a replaced cert file is invisible** | Fixed (LAB-749): certs read `certs:report --ssl-enabled` then `certs:show <app> crt` and compare the crt with the file in `up` and `diff`, using `certs:update` for a changed one; `checks:`, global domains, global logs and global nginx read before they write. A harness (`src/tests/in-sync.test.ts`) declares every resource and requires an in-sync server to get no command from `up`. | 2 |
| F2 | ✅ **Datastore `version` and `image` changes ignored** | `postgres:` and `redis:` run `:create` when the service is missing and skip it otherwise. A changed `version` or `image` is shown by `diff` as drift and warned about by `up`; applying it with `:upgrade` is left out on purpose (an upgrade can need a dump and downtime) and would need an explicit opt-in. | 3 |
| F3 | **Postgres backup state kept outside Dokku** | The backup config is tracked as a hash in the global env var `DOKKU_COMPOSE_BACKUP_HASH_<SERVICE>`, which Dokku merges into every app's environment. A change made on the server is never seen, and removing `backup:` leaves the schedule and credentials in place. Read the real state (`:backup-schedule-cat`, the 2.x `backup-*` properties), run `:backup-unschedule`/`:backup-deauth` when the block goes, add encryption, drop the env var. | 5 |
| F4 | **Global `env:` and `docker_auth:` only ever add** | Top-level `env:` runs `config:set --global` on every `up` and never unsets a key removed from the file. `docker_auth:` runs `registry:login` on every `up` and never logs out. Track global keys with a managed-keys marker as app `env:` does; use `registry:auth-status` (new in 0.38) to skip a login that already matches, and `registry:logout` for a removed server. | 3 |
| F5 | **Property lists behind Dokku 0.38.31** | See [Properties](#properties). `diff` and `--prune` cannot see, and `validate` cannot catch, keys missing from dokku-compose's lists: nginx `nginx-conf-sigil-path`, `nginx-service-command`; logs (global) `vector-image`, `vector-networks`; `ps:` rejects `restore`, `skip-deploy`, `start-cmd`, `dockerfile-start-cmd`; network `static-web-listener`; proxy `type`, `proxy-port`, `proxy-ssl-port`; scheduler `shell`; builder `selected`, `skip-cleanup`; git `keep-git-dir`, `rev-env-var`, `source-image`, `archive-max-files`, `archive-max-size`. `checks:` accepts any key though only `wait-to-retire` is valid. `REGISTRY_KEYS` lists `auth-servers`, which is report-only: an app with its own registry login would show it as removed, and `--prune` would fail running `registry:set <app> auth-servers`. Pin the lists in a test against the audited Dokku version. | 3 |
| F6 | **Link options** | `links:` runs `:link` with no options, so the URL always lands in `DATABASE_URL`/`REDIS_URL`. Add `alias`, `env_var` and `querystring` (`--alias`, `--env-var`, `--querystring`), which a second database on one app needs. | 2 |
| F7 | **Redis backups** | dokku-redis has the same backup commands as dokku-postgres; `redis:` has no `backup:`. Do it after F3 so both share one implementation. | 2 |
| F8 | **Datastore settings after create** | No create flag beyond `--image`/`--image-version`, and no `:set`. dokku-postgres/redis 2.x make every setting a reconcilable `:set` property: `memory`, `shm-size`, `custom-env`, `config-options`, `initial-network`, `post-create-network`, `restart-policy`, `log-driver`, `log-opt`, `expose-*`, plus `:mount`. | 5 |
| F9 | **Named storage entries** | Dokku 0.38 adds named entries (`storage:create` with `--chown`, `storage:set`, `storage:destroy`) and deprecates `storage:ensure-directory`. Declaring entries would replace a manual `mkdir` + `chown 32767` step for each new mount. `storage:mount --replace` would also converge an app's mounts in one call. | 5 |
| F10 | **Global defaults for supported namespaces** | Global settings exist only for `domains`, `env`, `nginx`, `logs` and registry logins. Dokku also takes `--global` for `scheduler`, `registry:set`, `checks`, `ps`, `builder`, `network`, `proxy`, `git` and `app-json`. Box setup scripts run `git:set --global deploy-branch` by hand today. | 3 |

### Add new namespaces

| # | Item | Why | Size |
|---|---|---|:-:|
| A1 | **`resource:` limits and reservations** | `resource:limit` / `resource:reserve`, per app and per process type, for CPU, memory and more. A production box can cap memory with `docker_options.deploy: ["--memory=…"]` today, which covers every process type at once and does not show in `resource:report`. | 3 |
| A2 | **`cron:` settings** | `cron:set`: `maintenance` (app and global), `maintenance.<id>` (one task, what `cron:suspend`/`:resume` write), `mailto` and `mailfrom` (global). Task definitions stay in `app.json`. | 2 |
| A3 | **Git host auth** | `git:auth` (made idempotent by the new `git:auth-status`) and `git:allow-host`. Box setup scripts run `git:auth` by hand today. | 2 |
| A4 | **App locks and `apps:set`** | `apps:lock`/`apps:unlock` as a `locked:` key; global `apps:set disable-autocreation`. | 1 |
| A5 | **Build record retention** | `builds:set retention`, per app and global (new in 0.38). | 1 |
| A6 | **docker-local scheduler settings** | `scheduler-docker-local:set init-process`, `parallel-schedule-count`, per app and global. | 1 |
| A7 | **`ssh-keys:`** | Declare who can push to the server; converge with `ssh-keys:add`/`:remove`. | 3 |
| A8 | **Other builders and buildpacks** | `builder:set selected` plus the herokuish, pack, nixpacks, railpack and lambda settings, and `buildpacks:set --replace`/`set-property stack`. Not needed where every app deploys a prebuilt image. | 5 |
| A9 | **Other proxies** | caddy, haproxy, openresty and traefik `:set` properties and `:labels:add`/`:remove`, after F5 adds `proxy.type`. | 5 |
| A10 | **Other datastore plugins** | mysql, mariadb, mongo, rabbitmq, elasticsearch and the rest share dokku-postgres's command set, so one generic service module built after F2, F3 and F8 would cover them all. Also the letsencrypt plugin. | 5 |
| A11 | **Event logging toggle** | `events:on`/`events:off`, a server-wide setting. | 1 |
| A12 | **`scheduler-k3s`** | Not planned: a multi-node Kubernetes scheduler with its own large surface (26 commands and its own properties). Revisit only if a box moves to k3s. | — |
| A13 | **Plugin removal** | `plugin:uninstall` (or `disable`) when a plugin leaves `plugins:`, under `--prune`. | 1 |

## Won't add

These commands are actions or views, not settings, so a compose file has nothing to declare.
Every read-only command (`:report`, `:list`, `:info`, `:show*`, `:logs` and the like) is
also out, except where dokku-compose uses it to read state.

| Kind | Why not | Commands |
|---|---|---|
| Deploy triggers | Deploying code is the CI pipeline's job; dokku-compose sets up what a deploy runs into | `deploy`, `git:from-image`, `git:from-archive`, `git:load-image`, `git:sync` |
| Runtime actions | They change what is running now, not what is configured | `ps:start`, `ps:stop`, `ps:restart`, `ps:rebuild`, `ps:restore`, `run:stop`, `builds:cancel`, `checks:run`, `cron:run`, `:start`/`:stop`/`:restart`/`:pause` on datastores |
| One-off commands and shells | Interactive or one-shot by nature | `run`, `run:detached`, `enter`, `shell`, `storage:exec`, `:connect`/`:enter` on datastores |
| One-shot actions | A single change with no state to converge on | `apps:clone`, `apps:rename`, `certs:generate`, `domains:reset`, `git:generate-deploy-key`, `config:clear`, datastore `:clone`, `:promote`, `:reset` |
| Data operations | Move data, not configuration | datastore `:import`, `:export`, `:backup` (one backup now) |
| Maintenance | Cleanups and rebuilds an operator runs when needed | `cleanup`, `builds:prune`, `repo:gc`, `repo:purge-cache`, `network:rebuild`, `network:rebuildall`, `nginx:validate-config`, `proxy:clear-config`, `run:retire`, `storage:migrate`, `git:unlock`, datastore `:reexpose`, `:upgrade-cleanup` |
| Daemon control | Server-wide services, started by setup | `nginx:start`, `nginx:stop`, `nginx:reload`, `logs:vector-start`, `logs:vector-stop`, `caddy`/`haproxy`/`openresty`/`traefik` `:start`/`:stop` |
| Covered by another command | dokku-compose converges the same state another way | `ports:add`, `ports:remove`, `ports:clear` (via `ports:set`); `domains:add-global`, `domains:remove-global` (via `domains:set-global`); `docker-options:clear` (via add/remove); `config:import` (via `env:`); `git:initialize` (deploys do it); `plugin:install-dependencies` (install does it); `plugin:trigger` (internal) |
| Debugging | Temporary by intent | `trace:on`, `trace:off` |
| Not in Dokku | Deprecated, or listed in help but not implemented | `storage:ensure-directory` (use `storage:create`, F9); `certs:chain`, `certs:key`, `certs:rollback` |
| k3s storage | Only apply under `scheduler-k3s` (A12) | `storage:annotations:*`, `storage:labels:*`, `storage:wait` |

## Re-auditing a new Dokku release

The summary counts and the command tables are generated by `scripts/dokku-audit/generate.ts`
from Dokku's help text and two status files: `commands.tsv` (Dokku core) and `datastores.tsv`
(dokku-postgres and dokku-redis). The alternative proxies and `scheduler-k3s` take their status
by rule in the script. Everything else on this page is written by hand.

1. Clone the releases and run the generator:

   ```bash
   git clone -q --depth 1 --branch <tag> https://github.com/dokku/dokku.git /tmp/dokku
   git clone -q --depth 1 --branch <tag> https://github.com/dokku/dokku-postgres.git /tmp/dokku-postgres
   git clone -q --depth 1 --branch <tag> https://github.com/dokku/dokku-redis.git /tmp/dokku-redis
   bun scripts/dokku-audit/generate.ts /tmp/dokku /tmp/dokku-postgres /tmp/dokku-redis
   ```

   It writes nothing and names each problem when Dokku has a command with no status, or a
   status names a command Dokku no longer has. Add, change or remove those rows in the `.tsv`
   files and run it again. When a command's help text is hidden (`proxy:build-config`,
   `git:status`, `git:unlock`, `plugin:installed`), give it a description in the script; it
   checks the plugin still has that subcommand. The base commands (`cleanup`, `run`, `logs`
   and the rest) are not checked: confirm them with `dokku help` on the new release.

2. Compare the properties by hand:

   ```bash
   grep -rn -A30 -E 'DefaultProperties = |GlobalProperties = ' --include='*.go' /tmp/dokku/plugins | grep -E '"[a-z0-9.-]+":'
   grep -rn -E 'VALID_KEYS=|GLOBAL_KEYS=|GLOBAL_ONLY_KEYS=' /tmp/dokku/plugins
   grep -ohE 'postgres:set lollipop [a-z-]+' /tmp/dokku-postgres/README.md | sort -u
   ```

   Check each against [Properties](#properties) and against the lists in
   `src/resources/properties.ts`.

3. Update the header table and [Priorities](#priorities).

When dokku-compose gains a feature, change its rows in the `.tsv` files, rerun the generator,
and update [Properties](#properties) and [Priorities](#priorities).
