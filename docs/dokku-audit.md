## Summary

dokku-compose declares the settings of an app on one Dokku host: create, domains, ports, proxy,
nginx, certs, storage, networks, env, scale, process settings, checks, logs, registry,
scheduler, builder (Dockerfile only), docker options, git properties, plugins, registry logins,
and postgres and redis services with links and S3 backups (encrypted or not).

The gaps fall into two groups:

1. **Gaps in features it already has.** Backups cannot authenticate with an instance role,
   datastores take no settings after create, storage mounts are plain bind
   mounts with no named entries, and most namespaces have no global defaults. These come
   first in [Priorities](#priorities).
2. **Namespaces it does not touch.** `resource`, `cron`, `git:auth`, `apps:lock`, `builds`,
   `scheduler-docker-local`, `ssh-keys`, non-Dockerfile builders and buildpacks, the other
   proxies, other datastore plugins and `scheduler-k3s`.

## Priorities

Fix the features dokku-compose already has before adding new namespaces: a user who declares
one of those keys today gets a wrong or noisy result. Sizes are story points. Status uses the
legend's marks, with the PRs that changed the item: ✅ done (the Notes
say what shipped), 🟡 partial (shipped, with what is left in the Notes), ❌ to do, ⛔ not planned.

### Fix existing features

| # | Item | Status | Notes | Size |
|---|---|---|---|:-:|
| F1 | **Settings re-applied on every `up`; a replaced cert file is invisible** | ✅ [#18](https://github.com/guess/dokku-compose/pull/18) | Certs read `certs:report --ssl-enabled` then `certs:show <app> crt` and compare the crt with the file in `up` and `diff`, using `certs:update` for a changed one; `checks:`, global domains, global logs and global nginx read before they write. A harness (`src/tests/in-sync.test.ts`) declares every resource and requires an in-sync server to get no command from `up`. | 2 |
| F2 | **Datastore `version` and `image` changes ignored** | ✅ [#19](https://github.com/guess/dokku-compose/pull/19) | `postgres:` and `redis:` run `:create` when the service is missing and skip it otherwise. A changed `version` or `image` is shown by `diff` as drift and warned about by `up`; applying it with `:upgrade` is left out on purpose (an upgrade can need a dump and downtime) and would need an explicit opt-in. | 3 |
| F3 | **Postgres backup state kept outside Dokku** | ✅ [#27](https://github.com/guess/dokku-compose/pull/27) | Backups are read from `postgres:info --format json` and compared (credentials by `backup-auth-fingerprint`), `backup: false` runs `:backup-unschedule --id default`/`:backup-deauth` and clears encryption and settings, and the `DOKKU_COMPOSE_BACKUP_HASH_*` env vars are unset. `backup.encryption` (`{ passphrase }` or `{ public_key_id, keyserver? }`, `false` clears) is applied with `:set backup-encryption-passphrase`/`backup-public-key-id`/`backup-keyserver` and compared by `backup-encryption-fingerprint` and exact strings, so the four `:backup-*-encryption` commands stay unused. Optional `storage_class`, `object_name`, `mailto` and `timestamp: false` go through `:set`. `validate` mirrors the plugin's set-time checks and rejects both encryption forms and the `REPLACE_ME` placeholder `export` writes. An absent `encryption:` is a `diff` note and `--prune` only warns. Passphrases are masked completely in logs, stderr, `diff` and `export`. A bucket-only change re-runs `:backup-schedule` when another schedule exists, and `diff` notes schedules other than `default` (plugin 2.5.0+), which `up` never touches. Both plugins share `src/modules/service-backup.ts`. Authenticating with an instance role is F11. | 5 |
| F4 | **Global `env:` and `docker_auth:` only ever add** | ✅ [#23](https://github.com/guess/dokku-compose/pull/23) | Global `env:` keeps the marker `DOKKU_COMPOSE_GLOBAL_MANAGED_KEYS`, sets only changed keys and unsets marked keys removed from the file; `docker_auth:` skips a login `registry:auth-status` reports as matching, logs in with `--password-stdin`, and `up --prune` runs `registry:logout` for a server the file does not list. Dokku floor raised to 0.38.29. | 3 |
| F5 | **Property lists behind Dokku 0.38.31** | ✅ [#25](https://github.com/guess/dokku-compose/pull/25) | Every app-scope `:set` key of nginx, logs, ps, network, proxy, scheduler, builder, git, registry and checks is in a list, the schema and `validate`; `diff` and `--prune` see them all. `checks:` takes only `wait-to-retire` (plus `disabled`/`skipped`), and `registry:` rejects the report-only `auth-servers`. `src/tests/property-keys.test.ts` derives each namespace's settable keys from real Dokku 0.38.31 `<ns>:report --format json` output checked in under `src/tests/fixtures/dokku-0.38.31/reports/` and compares them with the lists. Keys Dokku writes itself (git `deploy-branch` and `source-image`, proxy `proxy-port` and `proxy-ssl-port`, ps `restore`) are compared only when declared and never counted as removals. Global scopes stay in F10. | 3 |
| F6 | **Link options** | ✅ [#24](https://github.com/guess/dokku-compose/pull/24) | A `links:` entry is a name or `{ service, alias?, env_var?, querystring? }`, passed as `--alias`, `--env-var`, `--querystring`. `diff` reads the variable and its querystring from the app's env; changed options unlink then link. | 2 |
| F7 | **Redis backups** | ✅ | `redis.<name>.backup` takes exactly the keys of postgres (`schedule`, `bucket`, `auth`, `encryption`, `storage_class`, `object_name`, `mailto`, `timestamp`, or `false`) through the same code, read from `redis:info --format json` (dokku-redis 2.4.0 reports the same `backup-*` keys, `backup-auth-fingerprint` included). Needs dokku-redis 2.3.1 or later; `export` writes the block too. | 2 |
| F8 | **Datastore settings after create** | ❌ | No create flag beyond `--image`/`--image-version`, and no `:set` beyond `backup-bucket`. dokku-postgres/redis 2.x make every setting a reconcilable `:set` property: `memory`, `shm-size`, `custom-env`, `config-options`, `initial-network`, `post-create-network`, `post-start-network`, `restart-policy`, `log-driver`, `log-opt`, `expose-*`, plus `:mount`. Needs a design first: which keys apply only at create or after a restart, masking `password` and `custom-env`, whether `expose` is worth it on Docker 29, and splitting the work. | 5 |
| F9 | **Named storage entries** | ❌ | Dokku 0.38 adds named entries (`storage:create` with `--chown`, `storage:set`, `storage:destroy`) and deprecates `storage:ensure-directory`. Declaring entries would replace a manual `mkdir` + `chown 32767` step for each new mount. `storage:mount --replace` would also converge an app's mounts in one call. Needs a design first: where entries live in the schema, how existing bind mounts map to them, and the Dokku release that added them. | 5 |
| F10 | **Global defaults for supported namespaces** | ❌ | Global settings exist only for `domains`, `env`, `nginx`, `logs` and registry logins. Dokku also takes `--global` for `scheduler`, `registry:set`, `checks`, `ps`, `builder`, `network`, `proxy`, `git` and `app-json`. Box setup scripts run `git:set --global deploy-branch` by hand today. Open question: top-level `nginx:` and `logs:` mean `--global`, but top-level `git:` is a default copied onto each app. | 3 |
| F11 | **Backups authenticating with an instance role (`use_iam`)** | ❌ | `backup.use_iam: true` for a service on a host with an instance role, making `backup.auth` optional (required otherwise). Applied with `:backup-schedule <svc> <schedule> <bucket> --use-iam` and read back from `backup-use-iam` in `<plugin>:info`. `backup-use-iam` is a property of the schedule, so `set backup-use-iam` and `set backup-bucket` fail without a schedule: `up` must (re)schedule rather than `:set` it, and `use_iam` without `schedule` is rejected by `validate`. Switching from credentials to an instance role also needs a decision on `:backup-deauth`. Postgres and redis, after F3 and F7. | 2 |

## Won't add

These commands are actions or views, not settings, so a compose file has nothing to declare.
Every read-only command (`:report`, `:list`, `:info`, `:show*`, `:logs` and the like) is
also out, except where dokku-compose uses it to read state.

| Kind | Why not | Commands |
|---|---|---|
| Deploy triggers | Deploying code is the CI pipeline's job; dokku-compose sets up what a deploy runs into | `deploy`, `git:from-image`, `git:from-archive`, `git:load-image`, `git:sync` |
| Runtime actions | They change what is running now, not what is configured | `ps:start`, `ps:stop`, `ps:restart`, `ps:rebuild`, `ps:restore`, `run:stop`, `builds:cancel`, `checks:run`, `cron:run`, `:start`/`:stop`/`:restart`/`:pause` on datastores |
| One-off commands and shells | Interactive or one-shot by nature | `run`, `run:detached`, `enter`, `shell`, `storage:exec`, `:connect`/`:enter` on datastores |
| One-shot actions | A single change with no state to converge on | `apps:clone`, `apps:rename`, `certs:generate`, `domains:reset`, `git:generate-deploy-key`, `config:clear`, datastore `:clone`, `:promote`, `:reset` |
| Data operations | Move data, not configuration | datastore `:import`, `:export`, `:backup` (one backup now) |
| Maintenance | Cleanups and rebuilds an operator runs when needed | `cleanup`, `builds:prune`, `repo:gc`, `repo:purge-cache`, `network:rebuild`, `network:rebuildall`, `nginx:validate-config`, `proxy:clear-config`, `run:retire`, `storage:migrate`, `git:unlock`, datastore `:reexpose`, `:upgrade-cleanup` |
| Daemon control | Server-wide services, started by setup | `nginx:start`, `nginx:stop`, `nginx:reload`, `logs:vector-start`, `logs:vector-stop`, `caddy`/`haproxy`/`openresty`/`traefik` `:start`/`:stop` |
| Covered by another command | dokku-compose converges the same state another way | `ports:add`, `ports:remove`, `ports:clear` (via `ports:set`); `domains:add-global`, `domains:remove-global` (via `domains:set-global`); `docker-options:clear` (via add/remove); `config:import` (via `env:`); `git:initialize` (deploys do it); `plugin:install-dependencies` (install does it); `plugin:trigger` (internal) |
| Debugging | Temporary by intent | `trace:on`, `trace:off` |
| Not in Dokku | Deprecated, or listed in help but not implemented | `storage:ensure-directory` (use `storage:create`, F9); `certs:chain`, `certs:key`, `certs:rollback` |
| k3s storage | Only apply under `scheduler-k3s` (A12) | `storage:annotations:*`, `storage:labels:*`, `storage:wait` |

## Re-auditing a new Dokku release

The summary counts and the command tables are generated by `scripts/dokku-audit/generate.ts`
from Dokku's help text and two status files: `commands.tsv` (Dokku core) and `datastores.tsv`
(dokku-postgres and dokku-redis). The alternative proxies and `scheduler-k3s` take their status
by rule in the script. Everything else on this page is written by hand.

1. Clone the releases and run the generator:

   ```bash
   git clone -q --depth 1 --branch <tag> https://github.com/dokku/dokku.git /tmp/dokku
   git clone -q --depth 1 --branch <tag> https://github.com/dokku/dokku-postgres.git /tmp/dokku-postgres
   git clone -q --depth 1 --branch <tag> https://github.com/dokku/dokku-redis.git /tmp/dokku-redis
   bun scripts/dokku-audit/generate.ts /tmp/dokku /tmp/dokku-postgres /tmp/dokku-redis
   ```

   It writes nothing and names each problem when Dokku has a command with no status, or a
   status names a command Dokku no longer has. Add, change or remove those rows in the `.tsv`
   files and run it again. When a command's help text is hidden (`proxy:build-config`,
   `git:status`, `git:unlock`, `plugin:installed`), give it a description in the script; it
   checks the plugin still has that subcommand. The base commands (`cleanup`, `run`, `logs`
   and the rest) are not checked: confirm them with `dokku help` on the new release.

2. Compare the properties by hand:

   ```bash
   grep -rn -A30 -E 'DefaultProperties = |GlobalProperties = ' --include='*.go' /tmp/dokku/plugins | grep -E '"[a-z0-9.-]+":'
   grep -rn -E 'VALID_KEYS=|GLOBAL_KEYS=|GLOBAL_ONLY_KEYS=' /tmp/dokku/plugins
   grep -ohE 'postgres:set lollipop [a-z-]+' /tmp/dokku-postgres/README.md | sort -u
   ```

   Check each against [Properties](#properties) and against the lists in
   `src/resources/properties.ts`.

3. Update the header table and [Priorities](#priorities).

## Tracking work

[Priorities](#priorities) is the tracker for dokku-compose; there is no issue tracker. Each
item ships in a PR that changes this page, the reference docs and the code together, so the
docs never trail the code:

1. **The first commit is the design, and changes docs only.** Edit
   `docs/reference/<module>.md` in place so it describes what the PR ships: the YAML keys,
   their values and the Dokku commands they run. Write it as the current reference, never as a
   "Proposed" or "Plan" section; the reference docs always describe the latest behaviour. Rewrite
   the item's Notes to say what will change; its Status stays ❌. Reasons and rejected options go
   in the PR description. This commit is the contract: agree it before writing code.
2. **Later commits make the docs true.** Split a big change into several commits (schema,
   resource, `diff`, `export`, …). Implementation plans are working notes and stay out of the
   repo (`docs/plans/` is ignored).
3. **The last commit closes the item.** Set Status to ✅ (or 🟡, naming what is left in the
   Notes) with the PR's link, and rewrite the Notes to say what shipped. Change the item's rows
   in the `.tsv` files, rerun the generator (step 1 of
   [Re-auditing](#re-auditing-a-new-dokku-release)), update [Properties](#properties) and add
   the `CHANGELOG.md` entry.

An item too big for one PR lists its planned parts in its Notes; each PR ships one part and
leaves the Status 🟡 until the last. New work gets a row with the next free `F` or `A` number;
work that is not a Dokku command or property (a CLI flag, a bug in `diff`) needs no row, and its
PR and the changelog are the record.

Commits, PRs and the changelog name the item (`F10`, `A3`) and the PR, never an external
ticket. The page is public: describe setups generically ("a production box"), never by a
private app, host or domain name.

`src/tests/audit.test.ts` fails when the code runs a Dokku command the `.tsv` files do not
mark supported, when they mark one the code no longer names, or when the generated tables
were edited by hand instead of regenerated.
